## Scope

Datoviz v0.4 is a C-first rewrite of the rendering engine. RC1 is the API and architecture
candidate: it is intended for early testers of the scene/app runtime, raw Python bindings, packaging
route, and experimental browser/provider slices.

Release-facing surfaces:

- native scene/app path: scene, figure, panel, retained visuals, controllers, app/offscreen, capture;
- public C headers and installed CMake/pkg-config consumer metadata;
- raw generated Python `ctypes` binding;
- release example set and generated C reference outline;
- WebGPU/WASM experimental subset for promoted live examples;
- compute+graphics experimental slice;
- Qt/PyQt hosted rendering through the optional `datoviz_qtbridge` provider.

Not part of v0.4:

- v0.3 source or ABI compatibility;
- the old object-oriented Python plotting API;
- high-level statistical plotting, notebook/dashboard/napari workflows, and publication vector
  export, which belong above Datoviz in GSP/VisPy2/Matplotlib;
- full WebGPU parity with native Vulkan;
- a general compute framework.

## Known Issues And Limitations

- Windows AMD64 and Windows ARM64 wheels remain pending until local Windows proof and full wheel CI
  matrix confirmation pass.
- Release-target `macosx_11_0_arm64` remains pending until CI or an older-target builder proves it.
- Explicit linear `f16`/`f32` scientific image export/readback is deferred beyond RC1; v0.4.0
  capture is sRGB RGBA8.
- WebGPU/WASM supports the promoted example subset only; unsupported features should report clear
  diagnostics rather than silently diverging from native scene semantics.
- Compute+graphics is experimental and should not be treated as a general compute framework.
- Qt/PyQt hosting requires the optional `datoviz_qtbridge` provider, compatible Qt/PyQt Vulkan
  bindings, and platform WSI support. The base wheel must still install and import without Qt.
- The system PyQt6 package on the current Linux validation host lacks `QVulkanInstance`; valid PyQt
  proof used an isolated PyQt6 wheel.
- v0.4 does not preserve v0.3 source or ABI compatibility.


## Migration Notes

For v0.3 users:

- Rewrite code against the v0.4 C scene/app API or the generated raw Python `ctypes` layer.
- Do not expect old Python object-oriented plotting names to exist in Datoviz v0.4.
- Use GSP/VisPy2 for high-level Python plotting workflows as that layer becomes available.
- Treat Datoviz as the interactive GPU backend and raster capture backend, not the publication
  PDF/SVG/vector export layer.
