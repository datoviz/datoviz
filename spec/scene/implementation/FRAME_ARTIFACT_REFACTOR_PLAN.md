# Scene Frame Artifact Refactor Plan

Status: active v0.4 architecture refactor. Updated: 2026-06-09.

This plan defines the break-compatible migration from raw scene-emitted DRP2 streams to a single
frame artifact boundary. The refactor is intentionally broad: v0.4 should not carry a parallel
legacy stream-emission architecture.


## Goal

Make `DvzSceneFrameArtifact` the only scene emission product.

A `DvzDrp2CommandStream` remains the backend-neutral execution IR generated by the scene layer.
The stream is no longer the public scene lifetime boundary. It is owned by the emitted frame
artifact and exposed as an immutable stream snapshot when native runtime code needs DRP2 commands.

Target data flow:

```text
retained scene/figure
  -> DvzSceneFrameArtifact
       owns immutable DvzDrp2CommandStream snapshot
       owns frozen upload payload bytes
       owns setup/update/frame packet spans
       carries frame/resource counters and status hooks
  -> native app/runtime consumes artifact stream snapshot
  -> WASM/WebGPU consumes artifact packet spans
  -> JSON/debug export serializes the artifact stream snapshot
```


## Non-Goals

1. Do not remove DRP2 command streams.
2. Do not introduce a browser-only scene path.
3. Do not preserve `dvz_figure_emit()` or `dvz_figure_emit_ex()` as first-class scene architecture.
4. Do not make JSON the browser runtime transport.
5. Do not make retained-scene mutation legality depend on backend execution or stream destruction
   timing.


## Target Artifact Contract

`DvzSceneFrameArtifact` owns everything required to execute or inspect one emitted frame safely
after retained scene state changes:

1. an immutable `DvzDrp2CommandStream` snapshot;
2. frozen payload ownership for uploads that would otherwise point into mutable scene data;
3. encoded DRP2 setup, update, and frame packet spans for WASM/WebGPU;
4. resource-version and frame-index counters for retained runtime sessions;
5. status and diagnostics hooks for validation, unsupported features, and packet-encode failures;
6. future query, readback, and result-state ownership needed to match asynchronous results to the
   emitted frame that requested them.

Packet spans are borrowed views into artifact-owned memory. JSON strings may remain separately
allocated convenience exports, but they must be serialized from the artifact-owned stream snapshot.


## Public API Direction

Primary scene emission API:

```c
typedef struct DvzSceneFrameArtifact DvzSceneFrameArtifact;

DVZ_EXPORT DvzSceneFrameArtifact* dvz_figure_emit_frame(
    DvzFigure* figure, const DvzCapabilitySnapshot* caps, DvzDiagnosticReport* report,
    const DvzFramePlanEmitConfig* cfg);

DVZ_EXPORT void dvz_scene_frame_artifact_destroy(DvzSceneFrameArtifact* artifact);

DVZ_EXPORT const DvzDrp2CommandStream*
dvz_scene_frame_artifact_stream(const DvzSceneFrameArtifact* artifact);

DVZ_EXPORT char* dvz_scene_frame_artifact_json(
    const DvzSceneFrameArtifact* artifact, const char* name);
```

Packet accessors may be public, semi-public, or WASM-only depending on the API surface pass, but
they should use frame-artifact names. Keep `packet` terminology only for encoded setup/update/frame
packet spans and arenas.

Remove or explicitly demote:

1. `dvz_figure_emit()`;
2. `dvz_figure_emit_ex()`;
3. internal names centered on `DvzScenePacketArtifact` or `_scene_packet_artifact`.


## Architecture Invariants

1. Retained scene mutation is legal immediately after successful artifact creation.
2. Artifacts never borrow mutable visual payload memory.
3. Raw DRP2 stream access is a view of an artifact-owned snapshot, not the scene emission product.
4. JSON and packets are projections of the same artifact-owned stream snapshot.
5. Browser packet and arena spans are borrowed only until artifact release, the next emit, or scene
   destruction.
6. Native app/runtime and browser WebGPU share the same scene -> DRP2 lowering path.
7. Query/readback result ownership must not reintroduce live raw-stream lifetime constraints.


## Migration Series

Expect 8 to 10 commits for the full refactor including WASM/WebGPU. The preferred complete series is
9 commits:

1. **Architecture plan and stale docs cleanup**
   - Add this plan.
   - Clean lifecycle, integration, packet, WebGPU, and trace wording around the new boundary.

2. **Internal frame artifact rename**
   - Rename `DvzScenePacketArtifact` to `DvzSceneFrameArtifact`.
   - Rename `_scene_packet_artifact_*` to `_scene_frame_artifact_*`.
   - Keep packet wording only for packet span and arena accessors.

3. **Core artifact API**
   - Add `dvz_figure_emit_frame()`.
   - Add artifact destroy, stream, JSON, status, counter, and packet accessors.
   - Keep behavior equivalent to the current internal helper path.

4. **WASM C ABI unification**
   - Remove separate `scene->stream` ownership from `src/wasm/scene_api.c`.
   - Make JSON emission and packet emission use the same current frame artifact.
   - Tighten packet release and borrowed-span lifetime behavior.

5. **Browser WebGPU runtime artifact contract**
   - Update JS/WASM wrappers to treat packet sets as frame artifact projections.
   - Enforce borrowed-span, resource-version, frame-index, and reset rules.

6. **Native app/runtime migration**
   - Make app/runtime consume frame artifacts and retrieve the artifact stream snapshot for DRP2
     execution.
   - Update trace comments and docs to say frame artifact stream snapshot.

7. **Scene and native tests migration**
   - Move scene emission tests to the artifact API.
   - Keep direct stream tests only where they are DRP2-level tests.

8. **WASM/WebGPU tests and fixtures**
   - Prove packet emission from artifacts.
   - Prove JSON serialization from artifacts.
   - Keep browserless packet proof and WebGPU fixture runner coverage current.

9. **Public API cleanup and final docs**
   - Remove or explicitly demote `dvz_figure_emit()` and `dvz_figure_emit_ex()`.
   - Update API surface docs, generated-reference expectations, lifecycle docs, packet docs, and
     WebGPU subset docs.

If query/readback ownership needs deeper surgery, split it into a tenth commit after WASM/WebGPU
tests and before final API cleanup.


## Validation

Use the narrowest loop while iterating, then broaden before API cleanup:

1. focused scene artifact lifetime tests;
2. focused JSON-from-artifact tests;
3. focused packet-from-artifact tests;
4. WASM scene packet smoke;
5. WebGPU fixture preflight and browserless packet proof;
6. native app/runtime smoke where Vulkan is available;
7. `just build`;
8. `just test scene`;
9. `just test app`;
10. `just spec-check`;
11. `git diff --check`.

Before each commit, run the repository hygiene checks from `AGENTS.md` and verify no generated
payloads, vendored runtime libraries, `data` gitlink updates, or unrelated user changes are staged.
