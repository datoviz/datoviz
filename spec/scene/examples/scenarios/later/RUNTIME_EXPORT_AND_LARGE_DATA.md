# Later Runtime, Export, Diagnostics, And Large Data

> **Example status:** later planning bundle
> **Target:** runtime confidence and engine-user diagnostics
> **Data:** synthetic or prepared stress bundles
> **Validation:** smoke, performance, capture, and diagnostic correctness checks


## `advanced_runtime_export`

Native multi-window/fullscreen/HiDPI variants, high-resolution capture, transparent-background
export, batch/server-side rendering, camera bookmarks, and remote/cloud/thin-client workflows need
dedicated design before becoming public gallery examples.


## `visual_diagnostics`

Coordinate grids, picking-id views, draw-call grouping, GPU buffer-update visualization, pass graph
inspection, and other engine diagnostics are valuable but should remain developer-oriented until the
scene diagnostics API is explicit.


## `large_data_strategy_gallery`

Density rendering, progressive refinement, tile streaming, GPU instancing, sparse updates, and
out-of-core resources need explicit resource semantics before becoming gallery promises.
